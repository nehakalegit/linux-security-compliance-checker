# linux-security-compliance-checker
linux-security-compliance-checker

| #  | Security control / compliance check | Why is it a risk?                                                                                                                                   | Expected secure configuration                                                                                              | Remediation                                                                                             |
| -- | ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 1  | **SSH Root Login**                  | Direct root login gives an attacker immediate privileged access if root credentials are compromised.                                                | Root SSH login should be disabled: `PermitRootLogin no`                                                                    | Set `PermitRootLogin no` in SSH configuration and reload/restart `sshd`.                                |
| 2  | **SSH Password Authentication**     | Password-based SSH is more exposed to brute-force and credential attacks than key-based authentication.                                             | Prefer `PasswordAuthentication no` where SSH key authentication is implemented.                                            | Configure SSH key authentication, then set `PasswordAuthentication no` and reload/restart `sshd`.       |
| 3  | **SELinux Status**                  | Disabling SELinux removes mandatory access-control protections that can limit the impact of compromised processes.                                  | SELinux should be enabled and normally operating in **Enforcing** mode.                                                    | Configure SELinux as `enforcing` and ensure an appropriate policy is active.                            |
| 4  | **Audit Service (`auditd`)**        | Without auditing, important security events and system activity may not be recorded, reducing accountability and incident investigation capability. | `auditd` should be installed, enabled and running.                                                                         | Install `audit`, enable `auditd` at boot and start the service.                                         |
| 5  | **Host Firewall**                   | Without a properly configured firewall, unnecessary network services/ports may be reachable by attackers.                                           | A supported host firewall should be enabled and appropriately configured.                                                  | Enable the selected firewall mechanism and permit only required network traffic.                        |
| 6  | **IPv4 Forwarding**                 | IP forwarding can cause a normal server to route traffic between networks, increasing attack surface when routing is not required.                  | For systems **not intended to act as routers**, `net.ipv4.ip_forward = 0`.                                                 | Set `net.ipv4.ip_forward = 0` through `sysctl` configuration and apply the setting.                     |
| 7  | **Password Maximum Age**            | Passwords that remain valid indefinitely may allow compromised credentials to remain usable for long periods.                                       | Password aging should comply with the organization's defined password policy. A common benchmark check is `PASS_MAX_DAYS`. | Configure an appropriate `PASS_MAX_DAYS` in `/etc/login.defs` and update existing accounts as required. |
| 8  | **`/etc/passwd` Permissions**       | Incorrect permissions could allow unauthorized modification of account information.                                                                 | File should be owned by `root:root` with permissions consistent with the applicable RHEL CIS benchmark/profile.            | Correct ownership and permissions using `chown`/`chmod` as required by the selected benchmark.          |
| 9  | **`/etc/shadow` Permissions**       | `/etc/shadow` contains password hashes and other sensitive authentication information. Excessive permissions can expose credentials.                | Access should be restricted to privileged users/groups according to the applicable RHEL CIS recommendation.                | Correct `/etc/shadow` ownership and permissions according to the selected benchmark/profile.            |
| 10 | **Cron Configuration Permissions**  | Weak permissions on cron configuration can allow unauthorized users to modify scheduled commands and potentially execute malicious tasks.           | Cron configuration files/directories should have restricted ownership and permissions.                                     | Set appropriate `root` ownership and restrictive permissions on cron configuration files/directories.   |
