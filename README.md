|      # | Security Control / Compliance Check     | Why is it a Risk?                                                                                            | Expected Secure Configuration                                                      | Remediation                                                                                    |
| -----: | --------------------------------------- | ------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
|  **1** | **SSH Root Login**                      | Direct root login can give an attacker immediate privileged access if credentials are compromised.           | `PermitRootLogin no`                                                               | Set `PermitRootLogin no` in SSH configuration and reload/restart `sshd`.                       |
|  **2** | **SSH Password Authentication**         | Password authentication is more exposed to brute-force and credential attacks than key-based authentication. | Prefer `PasswordAuthentication no` when key-based authentication is implemented.   | Configure SSH keys, disable password authentication, and reload `sshd`.                        |
|  **3** | **SELinux Status**                      | Disabling SELinux removes mandatory access controls that can contain compromised applications.               | SELinux enabled and **Enforcing**.                                                 | Configure SELinux to `enforcing` and ensure an appropriate policy is active.                   |
|  **4** | **Audit Service (`auditd`)**            | Without auditing, important security events may not be recorded, making investigations difficult.            | `auditd` installed, enabled and running.                                           | Install `audit`, enable `auditd`, and start the service.                                       |
|  **5** | **Host Firewall Status**                | An inactive firewall can expose unnecessary network services and ports.                                      | A supported host firewall should be enabled and appropriately configured.          | Enable the firewall and allow only required traffic.                                           |
|  **6** | **IPv4 Forwarding**                     | A server could unintentionally route traffic between networks, increasing its attack surface.                | For non-router systems: `net.ipv4.ip_forward = 0`                                  | Set the parameter to `0` through persistent `sysctl` configuration and apply it.               |
|  **7** | **Password Maximum Age**                | Passwords that never expire may allow compromised credentials to remain useful for long periods.             | `PASS_MAX_DAYS` should meet the organization's/CIS profile's password policy.      | Configure `PASS_MAX_DAYS` and update existing accounts where required.                         |
|  **8** | **`/etc/passwd` Permissions**           | Unauthorized modification could alter user/account information.                                              | Owned by `root:root` with permissions meeting the selected benchmark.              | Correct ownership with `chown` and permissions with `chmod`.                                   |
|  **9** | **`/etc/shadow` Permissions**           | The file contains sensitive password hashes. Excessive access could expose authentication data.              | Restricted ownership and permissions according to the selected RHEL benchmark.     | Correct ownership and permissions on `/etc/shadow`.                                            |
| **10** | **Cron Permissions**                    | Unauthorized modification of scheduled tasks could allow malicious commands to execute automatically.        | Cron files/directories restricted to authorized administrators.                    | Correct ownership and permissions on cron configuration.                                       |
| **11** | **SSH Empty Passwords**                 | Accounts without passwords could potentially be accessed remotely.                                           | `PermitEmptyPasswords no`                                                          | Set `PermitEmptyPasswords no` and reload `sshd`.                                               |
| **12** | **SSH Maximum Authentication Attempts** | Unlimited/repeated authentication attempts increase brute-force opportunities.                               | `MaxAuthTries` set to an appropriately restricted value.                           | Configure `MaxAuthTries` according to the selected security baseline.                          |
| **13** | **SSH Idle Session Timeout**            | Abandoned authenticated sessions can be hijacked by someone with access to the terminal.                     | Appropriate `ClientAliveInterval` and `ClientAliveCountMax` values.                | Configure SSH idle-session timeout settings and reload `sshd`.                                 |
| **14** | **SSH Access Restrictions**             | Allowing every account to attempt SSH increases the number of accounts exposed remotely.                     | SSH access limited to authorized users/groups where appropriate.                   | Configure `AllowUsers`, `AllowGroups`, `DenyUsers`, or `DenyGroups` as required.               |
| **15** | **Password Minimum Length**             | Short passwords are generally easier to guess or brute-force.                                                | Minimum password length meets the organization's security policy.                  | Configure password-quality/PAM settings to enforce minimum length.                             |
| **16** | **Password Complexity / Quality**       | Weak passwords based on simple patterns are easier to compromise.                                            | Password quality requirements enforced through PAM/password-quality configuration. | Configure `pam_pwquality`/`pwquality.conf` according to policy.                                |
| **17** | **Password Minimum Age**                | Users could repeatedly change passwords to bypass password-history requirements.                             | Minimum password age defined according to security policy.                         | Configure `PASS_MIN_DAYS` and update existing accounts where necessary.                        |
| **18** | **Inactive Account Lock**               | Dormant accounts can remain available to attackers even though legitimate users no longer require them.      | Inactive accounts disabled after the organization's defined period.                | Configure account inactivity settings and disable unnecessary dormant accounts.                |
| **19** | **Failed Login Lockout**                | Unlimited password attempts make brute-force/password-spraying attacks easier.                               | Accounts temporarily locked after the defined number of failed attempts.           | Configure PAM `faillock` according to the approved baseline.                                   |
| **20** | **Root Account UID**                    | Another account with UID `0` effectively possesses root privileges.                                          | Only authorized root account(s) should have UID `0`; normally only `root`.         | Identify unauthorized UID 0 accounts and change/remove them.                                   |
| **21** | **Accounts Without Passwords**          | An account without valid authentication protection may permit unauthorized access.                           | No unauthorized accounts with empty password fields.                               | Lock the account or configure an appropriate password/authentication mechanism.                |
| **22** | **Duplicate UIDs**                      | Multiple users sharing a UID make accountability and attribution difficult.                                  | Each normal user should have a unique UID.                                         | Assign unique UIDs and correct affected file ownership.                                        |
| **23** | **Duplicate GIDs**                      | Duplicate group IDs can cause ambiguous permissions and unexpected access.                                   | Groups should have unique GIDs.                                                    | Assign unique GIDs and review affected group/file permissions.                                 |
| **24** | **World-Writable Files**                | Any local user may modify world-writable files, potentially enabling tampering or privilege abuse.           | No unnecessary world-writable files.                                               | Remove world-write permission where it is not explicitly required.                             |
| **25** | **Unowned Files**                       | Files without a valid owner can indicate deleted accounts or poor access-control management.                 | Files should normally have valid, authorized owners.                               | Assign an appropriate owner or remove unnecessary files after investigation.                   |
| **26** | **Ungrouped Files**                     | Files referencing nonexistent groups can create unclear or inappropriate access controls.                    | Files should have valid group ownership.                                           | Assign an appropriate existing group after investigation.                                      |
| **27** | **Core Dumps**                          | Core dumps can contain passwords, encryption material, tokens, or other sensitive process memory.            | Core dumps restricted/disabled according to the system's security requirements.    | Configure limits/system settings to restrict core-dump creation and storage.                   |
| **28** | **Unnecessary Services**                | Every unnecessary running service increases the system's potential attack surface.                           | Only business-required services should be enabled/running.                         | Disable and remove unnecessary services after confirming they are not required.                |
| **29** | **Time Synchronization**                | Incorrect system time can make audit logs, incident timelines, authentication, and correlation unreliable.   | Approved time-synchronization service configured and operating.                    | Configure an approved NTP/Chrony source and enable the time-sync service.                      |
| **30** | **Login Warning Banner**                | Systems without an approved access warning may not clearly communicate authorized-use requirements.          | Approved login/remote-access warning banner configured where required by policy.   | Configure the organization's approved banner in the applicable banner files/SSH configuration. |
