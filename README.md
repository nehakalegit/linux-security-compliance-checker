| #      | Security Control / Compliance Check     | Why is it a Risk?                                                                                                       | Expected Secure Configuration                                                          | Remediation                                                                              |
| ------ | --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| **1**  | **Audit Service (`auditd`)**            | Without auditing, important security events may not be recorded, making investigations difficult.(Impair Defenses)                       | `auditd` installed, enabled and running.                                               | Install and enable `auditd`, then start the service.                                   |
| **2**  | **Host Firewall Status**                | An inactive firewall can expose unnecessary ports and services.(Network Service Discovery)                                                         | A supported host firewall should be enabled and running.                               | Enable the firewall and allow only required traffic.                                     |
| **3**  | **SSH X11 Forwarding**                  | X11 forwarding can increase the SSH attack surface when it is not required.(Remote Services: SSH)                                             | `X11Forwarding no`                                                                     | Set `X11Forwarding no` in SSH configuration and reload `sshd`.                           |
| **4**  | **Login Warning Banner**                | Without a warning banner, authorized-use requirements may not be clearly communicated.                                  | Approved login warning banner configured.                                              | Configure an approved banner in `/etc/issue` or the applicable SSH banner configuration. |
| **5**  | **Password Maximum Age**                | Passwords that remain valid indefinitely can allow compromised credentials to remain useful longer.(Valid Accounts)                    | `PASS_MAX_DAYS` meets the organization's security policy.                              | Configure `PASS_MAX_DAYS` appropriately.                                                 |
| **6**  | **Password Minimum Age**                | Users may repeatedly change passwords to bypass password-history requirements.((Valid Accounts))                                        | `PASS_MIN_DAYS` meets the organization's policy.                                       | Configure `PASS_MIN_DAYS` appropriately.                                                 |
| **7**  | **SELinux Status**                      | Disabling SELinux removes mandatory access controls that can restrict compromised applications. (Impair Defenses: Disable or Modify Tools)                        | SELinux enabled and `Enforcing`.                                                       | Configure SELinux to `enforcing`.                                                        |
| **8**  | **SSH Empty Passwords**                 | Allowing empty passwords can expose accounts to unauthorized remote access.(Valid Accounts)                                           | `PermitEmptyPasswords no`                                                              | Set `PermitEmptyPasswords no` and reload `sshd`.                                         |
| **9**  | **SSH Maximum Authentication Attempts** | Too many login attempts make brute-force attacks easier.(Brute Force)                                                               | `MaxAuthTries` restricted according to the selected security baseline.                 | Configure an appropriate `MaxAuthTries` value.                                           |
| **10** | **SSH Idle Session Timeout**            | Unattended SSH sessions could be misused by someone gaining access to the terminal.(Valid Accounts)                                     | Appropriate `ClientAliveInterval` / `ClientAliveCountMax`.                             | Configure SSH idle timeout settings.                                                     |
| **11** | **SSH Password Authentication**         | Password authentication is more exposed to brute-force and credential attacks than properly managed key authentication.(Brute Force) | Prefer `PasswordAuthentication no` where key-based authentication is implemented.      | Configure SSH keys and disable password authentication where appropriate.                |
| **12** | **SSH Root Login**                      | Direct root login can give an attacker immediate privileged access if root credentials are compromised.(Valid Accounts)                 | `PermitRootLogin no`                                                                   | Set `PermitRootLogin no` and reload `sshd`.                                              |
| **13** | **Time Synchronization**                | Incorrect system time makes logs, authentication events and incident timelines unreliable.(Indicator Removal: Timestomp)                              | Approved time synchronization service configured and running.                          | Configure and enable Chrony/NTP as appropriate.                                          |
| **14** | **Unnecessary Services**                | Every unnecessary running service increases the system's attack surface.(Network Service Discovery)                                                | Only required services should be enabled/running.                                      | Disable unnecessary services after confirming they are not required.                     |
| **15** | **Cron Permissions**                    | Unauthorized modification of scheduled jobs could allow malicious commands to execute automatically.(Cron)                    | Cron configuration restricted to authorized administrators.                            | Correct ownership and permissions on cron files/directories.                             |
| **16** | **Failed Login Lockout**                | Unlimited failed login attempts make brute-force/password-guessing attacks easier.(Brute Force)                                     | Failed-login lockout configured according to policy, such as an approved `deny` value. | Configure `/etc/security/faillock.conf` according to the approved baseline.              |
| **17** | **`/etc/passwd` Permissions**           | Improper permissions could permit unauthorized modification of account information.(Account Manipulation)                                     | Permissions meet the selected security baseline.                                       | Correct permissions using `chmod`.                                                       |
| **18** | **Password Complexity / Quality**       | Weak passwords are easier to guess or crack.(Brute Force)                                                                          | Password-quality requirements enforced.                                                | Configure `pwquality.conf`/PAM according to policy.                                      |
| **19** | **Password Minimum Length**             | Short passwords are generally easier to brute-force or guess.(Brute Force)                                                           | Minimum password length meets the organization's policy.                               | Configure an appropriate minimum password length.                                        |
| **20** | **`/etc/shadow` Permissions**           | `/etc/shadow` contains password hashes and other sensitive authentication information.(OS Credential Dumping)                                  | Access restricted according to the selected RHEL security baseline.                    | Correct `/etc/shadow` ownership and permissions.                                         |
| **21** | **SSH Access Restrictions**             | Allowing all accounts to attempt SSH increases remote exposure.(Remote Services: SSH)                                                         | SSH access limited to authorized users/groups where required.                          | Configure `AllowUsers`, `AllowGroups`, `DenyUsers`, or `DenyGroups`.                     |
| **22** | **SSH Port Check**                      | Identifies whether SSH is listening on the default or organization-approved port.(Remote Services: SSH)                                       | SSH port configured according to organizational policy.                                | Configure the approved SSH port and corresponding firewall rules if required.            |
| **23** | **FTP Account Check**                   | An unnecessary FTP account can increase the number of accounts/services exposed on the system.(Valid Accounts)                          | Unnecessary FTP accounts should not exist or should be appropriately disabled.         | Remove/disable the FTP account/service if it is not required.                            |
| **24** | **`/etc/passwd` Owner**                 | Incorrect ownership could allow inappropriate control over account configuration.(Account Manipulation)                                       | `/etc/passwd` owned by `root`.                                                         | Run `chown root /etc/passwd` if ownership is incorrect.                                  |
| **25** | **`/etc/group` Owner**                  | Incorrect ownership could allow inappropriate modification of group information.(Account Manipulation)                                    | `/etc/group` owned by `root`.                                                          | Run `chown root /etc/group` if ownership is incorrect.                                   |
